04

Rubric · single-agent v1

What already exists, and what is new.

Every close method scored against the parameters a single-agent long-horizon router needs. Three famous request-level routers are included for reference. Highlighted rows, tagged New in the CPR column, are ones no method covers even partially; they carry the novelty claim, summarised just below.

Where CPR is new

No close method fills these rows, even partially.

D4Model and context chosen jointly

At a checkpoint, pick the model and the evidence packet (full history, compact handoff, or restart) as one action. Measure model ability, context sufficiency and cache cost separately.

Strongest claim. Every router below forwards the conversation unchanged; ACON and TRACE change context with a fixed model.
A4Timing compared head to head

Fixed prefix (SWE-Router), per-call (MTRouter) and adaptive checkpoints (TACIT-style) on the same states, model pool and budget.

Evaluation contribution. Each method reports against its own baselines; none compares timing policies on matched tasks.
E2 + A3Checkpoint decisions trained on measured continuation value

Label each stay/switch with paired continuations run from that same mid-run state, not from full-episode rollouts or a per-switch penalty table.

Moderate. TRACE uses paired continuations, but only to judge compaction; cite it and separate on what is decided.

Not claimed as new: decisions after the first prompt, episode-success training, budget in state, continuity locks and cache-aware switching. CPR adopts these from the methods below. The famous request-level routers (RouteLLM, FrugalGPT, Avengers-Pro, and the LiteLLM complexity router this repo uses today) score only on D1: they pick a model per query and keep no session state. They are the cost-saving baselines CPR must beat, not competitors for the novelty claim.

Hard locks during tool loops and provider-held state; idle and task-drift resets; switch score charges lost prompt cache, handoff and recent-switch penalties.Stops a per-request router from bouncing models mid-session and breaking cache or tool state.Continuity infrastructure and a baseline. SWE-RouterRuns Cheap for a fixed exploration prefix, then decides once: continue Cheap or restart Strong from the original task.Initial prompts hide how hard a software task is; a short exploration reveals it.Closest timing baseline. One fixed decision point and restart-only escalation; CPR adds in-place continuation, compact packets and adaptive timing.
TACIT-SwitchLearns a cumulative-risk threshold that triggers a one-way handoff from Cheap to Strong, trained on paired full rollouts and teacher-annotated timing.When to escalate permanently in an agent episode.Adaptive timing already exists. CPR labels decisions with continuations measured from the checkpoint itself, allows staying or switching back, and chooses the context too.
MTRouterPicks a model at every turn from history and candidate-model embeddings, supervised by terminal outcomes and future-error penalties.Per-turn routing that optimises the episode, not each call.Strongest per-call baseline. CPR must beat it when it is given the same state and a stay action; no context decision.
ReDActDefers individual uncertain actions to a stronger model, then returns to the cheap one.Local error risk in agent steps.Local risk versus remaining-episode value; temporary deferral, no context choice.
SeqRouteOffline-RL sequential router that conditions on the remaining session budget.Spending a fixed budget well across a multi-step session.Budget-in-state is prior art. No checkpoint branches, locks or context choice.
TwinRouterBenchBenchmark that branches intermediate prefixes, swaps model tiers and verifies downstream success, with live prompt-cache accounting.Evaluating per-step routers on real agent tasks.Branching benchmark and data source. CPR samples Cheap-created and degraded states and adds context alternatives.
ACONOptimises the compression guidelines an agent uses to compact its own history and observations.Long-horizon agents running out of context or paying for it.Compaction method, fixed model. CPR does not invent compression; it decides which packet to send to which model.
TRACEEvaluates compaction events by running paired continuations from the same environment state, with repeated seeds.Whether a compaction helped or hurt the rest of the run.Closest measurement method. CPR uses the same paired-continuation idea, but to value model × context choices rather than to judge compaction.
