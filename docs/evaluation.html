Evaluation

Test the claim—not a weaker opponent.

Each phase has a matched action space and baselines. Offline prediction is diagnostic; the decisive result is a fresh, closed-loop episode comparison including routing, context-transfer, and cache-loss overhead.

Required comparison families

  1. Always Cheap / always Strong: initial-state endpoints under identical scaffold and episode caps.
  2. Task-only and simple rules: initial Strong-success/difficulty predictors, repeated-failure escalation, and fixed stage/model tables where applicable.
  3. Avengers-Pro: original-request, retrained per-call, and retrained checkpoint-state variants.
  4. vLLM Semantic Router (session-aware): a versioned, explicitly configured baseline with its tool-loop/provider-state locks, cache-aware switch cost, and resets—not an unspecified product label.
  5. SWE-Router-like fixed prefix: development-selected prefix length and continue/restart threshold.
  6. TACIT-Switch-style handoff: paired-rollout/teacher-interval supervision under matched tasks, with annotation cost disclosed.
  7. ReDAct-style deferral: local uncertainty/risk intervention followed by Cheap; distinguish faithful reproduction from a logit-free analogue.
  8. MTRouter-like outcome-aware per-call: history and terminal labels, with a stay action. Equalize available state, model pool, and training budget.
  9. Phase 2 context policies: always-full, fixed compact/retrieval packets, and independently tuned model/context selectors versus joint selection.
  10. Phase 3 composed controller: independently tuned timing + model + context policies, under the same evidence, data, pool, and session caps as the integrated learner.

What to measure

Terminal successExecutable task checks; no LLM judge as the only correctness criterion.
Total episode spendPrefix, failed attempts, handoff generation, cache reads/writes, routing, and tools.
Wall time + tailsEnd-to-end latency, p50/p95, transfer time, tool waits, and cap violations.
Allocation valueContinuation/recovery value in Phase 1; context and budget effects across session stage later.
Prediction qualityPer-action calibration, Brier/log loss, ranking error, and uncertainty—not accuracy alone.
Decision overheadEncoder, gate, value prediction, serialization, and cache re-computation separately.
Routing behaviorTiming, stay/switch choices, context size, restart, and switch frequency.
GeneralizationHeld-out repositories/tasks, policy-induced states, and a later model-pair transfer test.
Context efficiencyPacket sufficiency, token/cache use, omitted evidence, and native/pool capacity separately.
Session continuityCache hits lost on switch, re-read tokens, lock-blocked switches, and switch thrash.
Primary operating pointMinimize total cost subject to a predeclared non-inferiority margin on terminal success, with an explicit latency budget.

Matched ablations

Hold state encoding and value prediction fixed across timing ablations in Phase 1. Phase 2 crosses model and context choices while fixing the reasoning budget. Phase 3 compares component policies, their simple composition, and the integrated controller. Report training volume and all overhead; do not attribute representation or extra-data gains to timing.

Statistical discipline

Choose prices, budgets, margins, thresholds, and primary outcomes before test evaluation. Use repeated runs and task/repository-clustered paired confidence intervals. Report absolute success-rate loss and cost reduction, failures, and all operating points; tune only on development data.

If reporting “retain 95% or 98% of Strong’s success,” define it as a relative success-rate target, not 95% task accuracy. Do not promise exact equality or superiority in advance.

Oracle and cost

Hindsight is a diagnostic—not a deployable policy.

A request-level “perfect oracle” uses known candidate outcomes. Here the diagnostic chooses among only the sampled checkpoint actions under their stated continuation protocols. Report it separately by phase and action menu; a Phase 1 selector says nothing about the optimum multi-revision policy.

Define the local hindsight selector

a*i = argmaxa ∈ Ai [p̂selectia − λĉselectia − ηℓ̂selectia]

Ai contains sampled feasible branches. Estimate success probability and mean resource use with repeated continuations; specify tie-breaking. Select with one repetition set and report with independent repetitions to reduce winner’s-curse bias.

Report every checkpoint, including cases where no branch succeeds. One lucky success among many rollouts is not the allocation’s expected success probability.

Keep three numbers separate

Deployment route cost: sunk prefix + selected remaining branch cost (including its transfer) + router overhead not already included. Never charge handoff twice.

Data-collection cost: actual prefix runs + all branch continuations and repetitions + snapshots, infrastructure, annotations, and evaluation. Do not sum the prefix again for each clone.

Diagnostic performance: independent outcome estimates for the selected sampled branch. A budget-constrained selector and an unconstrained success oracle are different diagnostics.

Not a global upper bound

This selector sees hindsight estimates only for the collected states and actions. It does not optimize every possible future policy, model, or context packet; finite noisy estimates may even underperform another policy. Call it a sampled-branch hindsight diagnostic, not a proven full-episode oracle ceiling.

Feasibility

Practical to pilot. Not yet justified to scale.

A credible first experiment

Small action space

  • One agent, two measured model endpoints.
  • A measured continuation menu before adaptive timing.
  • Quiescent, reproducible software sandboxes.
  • Small supervised predictors before complex RL.
  • A pilot sized to measure effect and noise before committing a larger data budget.
Not yet a credible promise

Unbounded control

  • Multi-agent graphs and arbitrary model pools.
  • Exhaustive branching across a whole episode.
  • Guaranteed frontier success at lower cost.
  • Assumed millisecond end-to-end router latency.
  • A fixed dollar budget derived from an unmeasured per-rollout price.
Measure before budgeting

Collection bill

prefix runs
+ Σ continuation trials
+ infrastructure
+ annotation / evaluation

Use pilot token/cache usage and runtimes for mean and tail estimates. Prices, model versions, repeated trials, failed branches, storage, and snapshot restoration must appear in the estimate.

Go / no-go decision

Evaluate each phase on its own incremental value and its stated dependencies. Scale a learned allocation only if it generalizes and improves terminal outcomes after routing, context-transfer, or cache-loss costs. A negative recovery result does not by itself invalidate context allocation; investigate those questions without assuming the failed component helps. Prefer simple rules where they match performance, and stop expanding the action space when its added complexity is not justified.

Proposed contributions

Evidence first. Algorithmic novelty only if earned.

01

A phased checkpoint dataset with reproducible state restoration, model/context allocation definitions, repeated outcomes, and complete resource accounting.

02

Evidence about which execution signals justify revising resource allocations, including—but not limited to—recovery, and how timing interacts with context needs.

03

A checkpoint controller evaluated against single-pass, per-call, fixed-prefix, adaptive-handoff, session-aware, and composed policies under matched phased action spaces.

04

Controlled tests of model–context effects within one agent session, plus evidence for or against integrating them under a shared episode budget.

Status: research formulation. No checkpoint controller, phased checkpoint dataset, or claimed success–cost result has been implemented in this repository.
